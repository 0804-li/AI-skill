# AI视频导演调度与镜头语言数据库

面向 Seedance 2.0 / 2.5 的导演级 Prompt 工程系统。核心理念：**AI视频 Prompt 不应该只描述"画面里有什么"，还必须描述人物怎么动、怎么走位、摄影机怎么动、环境怎么动、前后景怎么配合、镜头如何转场、运动如何保持连续稳定。**

## 核心结构：十二要素导演 Prompt

任何完整 AI 视频导演 Prompt 按以下逻辑组织（七层语言展开为十二要素）：

```
主体 + 人物动作 + 人物调度 + 人物关系 + 摄影机运动
+ 人物与摄影机速度关系 + 前景/中景/背景 + 环境运动
+ 空间视差 + 遮挡 + 转场 + 连续性与稳定性控制
```

在十二要素之上，精品电影级 Prompt 还需叠加**光色风格层**：光线设计（08号词库）+ 色彩叙事（09号词库）+ 导演风格签名（10号词库）。调度语言决定"怎么动"，光色风格决定"什么质感"——两层齐备才是完整的导演级 Prompt。

## 工作模式

进入某个模式后，先用下方总览表确认**加载条件、必加载词库的优先级顺序、以及应交付的输出物**，再按该模式的步骤执行。优先级数字越小越先加载、越核心。

### 模式加载总览（触发条件 / 必加载词库优先级 / 输出物）

| 模式 | 触发条件（加载条件） | 必加载词库（优先级 ①最高→⑥可选） | 输出物 |
|---|---|---|---|
| **A 从零生成** | 用户给场景/剧本/一句话创意，要单镜头 Prompt | ①`18`导演意图(决策入口) → ②`06`情绪场景/`02`运动/`03`景别 → ③`20`摄影机物理 → ④`24`行为控制(编译) → ⑤`25`Seedance执行(模板) → ⑥`08`/`09`/`10`质感(可选) | 单镜头导演级 Prompt + 导演设计说明 |
| **B 诊断改写** | 用户贴现成 Prompt / 求优化 / 求诊断 | ①`24`行为控制(形容词清洗+失败诊断树) → ②`25`质检六维 → ③`18`必要性测试 | 诊断表 + 改写版 Prompt |
| **C 查询教学** | 用户问术语/概念/中英对照 | 对应词库按需（`02`/`03`/`08`/`09`/`10`/`20`…） | 术语定义 + AI 写法 + 三级系统 |
| **D 分镜编排** | 用户给大纲/剧本要多镜头分镜 | ①`18`导演意图(每镜决策+信息接力) → ②`22`Coverage(镜头组模板) → ③`21`剪辑语法(切点/匹配/节奏) → ④`19`视觉心理(注意力) → ⑤`15`站位/`20`物理/`24`/`25` | 分镜表 + 每镜 Prompt + 跨镜状态账本 |

> 通用底层：`24` 行为控制引擎与 `25` Seedance执行层是**所有模式的通用编译/执行层**——任何模式在"把导演意图变成 AI 能执行的 Prompt"时都应经过 24（抽象词→变量、一镜一变量、形容词清洗）和 25（固定层+变量层、Prompt 顺序、质检）。

根据用户请求判断进入哪种模式。判断依据：用户给了场景/剧本 → 模式A；用户贴了现成 Prompt → 模式B；用户问术语/概念 → 模式C；用户给剧情大纲要多镜头 → 模式D；用户要做整片/多场景项目、关心跨镜一致性 → 模式E；用户给参考片/片名/经典场景描述、说"我想要XX那种感觉" → 模式F；用户涉及图生视频/首尾帧/尾帧继承/多参考图，或要求上下镜无缝衔接 → 模式G。

### 模式A：从零生成 Prompt

**加载优先级**：① `18`导演意图(决策入口) → ② `06`/`02`/`03`(选主镜头与运动) → ③ `20`摄影机物理(焦段/景深/机位) → ④ 类型词库(`16`打斗/`17`表演/`12`叙事) → ⑤ `24`行为控制(编译) → ⑥ `25`Seedance执行层(模板) → ⑦ `08`/`09`/`10`(质感,可选)。

1. 从用户输入提取：主体类型（人物/产品/建筑/东方场景/群像/打斗/情绪）、镜头目的（展示/强调/转场/叙事）。
2. 加载 `06-情绪与场景速查.md` 选择主镜头 + 0~2个辅助运动。**主体类型含打斗/追逐/对抗时必加载 `16-武术动作与动作指导.md`**：先建人物战斗DNA，再按Fight Beat节拍拆动作，用第十七章模板起稿。**主体含人物面部特写/对白/情绪表演时加载 `17-微表情与人物表演.md`**：按Prompt专业五层级写表演（动作层+时间层+意图层，不写"开心表情"），人物表演走Trigger→Processing→Reaction→Residual链条，特写只留一个主动作+一个辅助动作。
3. **先走 `18` 导演意图决策链（最高优先级）**：用"场景目标六大类 → 导演意图20类 → 镜头选择决策矩阵"确定本镜的 Scene Objective 与 Director Intent，明确信息控制（观众/角色信息差）、主体优先级、情绪×镜头距离。**未定意图前不急着选摄影机运动**——意图决定镜头，而非反过来。
4. 按十二要素逐层填充，需要具体词汇时加载对应词库；用 `20-摄影机物理与镜头光学系统.md` 落实光学参数：明确焦距(广角/标准/长焦)、景深(光圈)、机位距离与透视、对焦方式(Focus Lock/Rack)，核对 Camera State 六要素避免物理冲突。
5. **编译（必经 `24` 行为控制引擎）**：删除"电影感/震撼/唯美"等抽象形容词（走形容词清洗器），落实"一镜一主变量"与复杂度预算，用四段结构(状态/动作/摄影机/环境)组织。
6. **组装输出（`25` Seedance执行层）**：按 25 号的 Prompt 推荐顺序 + 固定层/变量层结构落 Prompt，单镜头用其十节模板，剧情/商业镜头用对应执行结构；有首帧/参考图时走 I2V 分支。
7. **质感升级（精品电影必做，可选）**：加载 `08-灯光.md` 设计光源方向与光型，加载 `09-色彩与视觉质感.md` 定主色调+强调色；用户点名风格或需要辨识度时，加载 `10-导演风格签名.md` 调用整套签名卡。光的动态变化（光斑流动/门开光涌入）优先于静态打光。
8. 输出后附"导演设计说明"：主镜头是什么、辅助运动是什么、光色如何设计、转场如何完成；并说明**本镜的 Director Intent 与 Start→End State**。
9. **用户提供了首帧/参考图或本镜属于多镜序列时**：改用 `26-图生视频分镜衔接工程.md` 的 I2V 六句式重写 Prompt（只写增量 + 收束定型句），并转模式G 设计上下镜接法。

### 模式B：改写/优化现有 Prompt

**加载优先级**：① `24`行为控制(形容词清洗+失败诊断树) → ② `25`质检六维 → ③ `18`必要性测试。

按七层逐层诊断用户 Prompt，输出诊断表后给改写版本：

| 检查项 | 诊断问题 |
|---|---|
| 主体动作 | 是否有明确动作与方向（从左向右/向镜头/远离）？ |
| 人物走位 | 是否说明入画方向、路径、与摄影机距离变化？ |
| 摄影机运动 | 是否明确主镜头运动？是否堆叠过多运动（推+拉+摇+移+环绕+甩+升降同框=运动逻辑混乱）？ |
| 人物与摄影机关系 | 是否写明速度关系（同步后退/平行跟拍）？ |
| 环境动态 | 背景是否完全静止（应加入云/雾/树叶/光影等次级运动）？ |
| 前后景配合 | 是否有前景遮挡/视差描述？ |
| 转场 | 是否说明如何进入下一镜头？ |
| 光线 | 是否有明确光源方向与光型？光是否有动机（画内可见来源）？是否有光的动态变化？ |
| 色彩 | 是否定了主色调+强调色？是否写了饱和度档位？色温是否有冷暖关系而非单色打亮？ |
| 连续稳定 | 是否缺少一致性约束（人物身份/服装/空间/光影/色彩基调跨镜锁定）？ |
| 图生视频衔接 | 是否重复描述了图中已有内容（应只写增量）？是否缺首帧锚定句与收束定型句（End State）？是否说明本镜尾帧如何交给下一镜？ |
| 形容词污染 | 是否大量使用"电影感/震撼/唯美"等空洞形容词（应翻译为可执行摄影动作）？ |

**修复输出**：先按 `24` 的"失败诊断树"定位问题类别（人物漂移/动作跳变/摄影机乱跑/背景变形/表情瞬切/光线乱跳/角色换衣），按"修复优先级"（先修大错→再修质感）只改一件事验证；改写版严格按 `25` 的质检六维（A身份/B空间/C运动/D摄影机/E表演/F世界）自检通过；凡"电影感/震撼/唯美"等抽象形容词一律经 `24` 形容词清洗器转译为可观测摄影变量。

### 模式C：镜头语言查询教学

1. 用户问术语（如"希区柯克变焦""180度规则"）→ 在词库中检索定义、作用、中英对照。
2. 给出该术语的 AI Prompt 写法（参考 `02-摄影机运动.md` 各节成品 Prompt）。
3. 用"三级系统"解释差异：LEVEL 1 描述（"一个男人站在桥上"）→ LEVEL 2 摄影（"低机位，中景，35mm，慢推"）→ LEVEL 3 导演（完整运动+空间+焦点+意图描述）。

### 模式D：多镜头分镜脚本编排

**加载优先级**：① `18`导演意图(每镜决策+信息接力) → ② `22`Coverage(镜头组模板) → ③ `21`剪辑语法(切点/匹配/节奏) → ④ `19`视觉心理(注意力) → ⑤ `15`站位/`20`物理/`24`/`25`。

1. 将剧情大纲拆解为镜头序列，**每个镜头只设计一个主动作**。
2. 每个镜头按模式A生成完整 Prompt。**每镜先经 `18` 导演意图决策链**：明确该镜的 Scene Objective、Director Intent、信息接力关系（上一镜传给本镜什么、本镜传给下一镜什么），再决定镜头策略，避免"为运动而运动"。
3. 镜头间必须设计转场（从 `05-转场与连续性.md` 选择：前景遮挡/人物擦镜/烟雾/穿越/甩镜/动作匹配等）；**用 `21-视觉剪辑语法与切点系统.md` 选择切点类型与匹配方式**：动作/图形/运动/色彩/概念 Match Cut，确定 Cut Point 与节奏曲线，避免无效跳切。
4. 使用 `assets/prompt-template.md` 中的分镜表输出：镜号｜景别｜主动作｜主镜头运动｜辅助运动｜前中后景｜转场｜完整Prompt。**用 `22-Coverage场景覆盖系统.md` 的 Coverage Matrix 核对覆盖度**：对话/动作/情绪戏分别确保 Master Shot + 正反打/宽中特覆盖齐备，避免镜头冗余或覆盖缺口。
5. 检查运动方向连续性（180度规则）：相邻镜头人物运动方向不要无故反转。**涉及多人物站位锁定/空间锚点/场景一致性时加载 `15-人物站位与场景一致性.md`**，确定人物锚点、固定区与变量区、首帧-尾帧继承关系。
6. 检查**跨镜光色连续性**：同场戏锁定色温基调、光源方向、人物服装色、环境主色（参考 `09-色彩与视觉质感.md` 色彩叙事节）；光影可随剧情递进，但同镜头组内不可无故漂移。
7. 涉及表演深度时参考 `12-叙事剧作与表演.md`：为每个镜头指定情绪强度（1-5）和变化节点，写明动作起点/终点/反应顺序；**涉及人物面部表演/对白/微表情时叠加 `17-微表情与人物表演.md`**——区分内心情绪与外显情绪、写潜台词、设计Reaction Delay和情绪余韵、镜头间用Performance State（首尾帧情绪继承）保持表演连续，聆听者必须有Listening Acting不能死脸；涉及声音和美术服化道时参考 `13-声音与美术服化道.md` 填充声音五层与空间叙事。
8. **图生视频/链式生成时（强烈推荐）**：加载 `26-图生视频分镜衔接工程.md`，为每个镜头补两列——「首帧来源」与「接法」，并明确本镜 End State（尾帧要停成什么样）。相邻镜头机位角度差 ≥30° 或景别跳 ≥2 级；出画方向 ↔ 入画方向必须匹配（右出必左入）；每 3~5 镜做一次锚点回注。正反打用母角色图单独生成，不链式继承。**链式/图生视频每镜的 Prompt 经 `24` 行为控制编译、按 `25` 执行层组装，并登记到跨镜状态账本（见 `26`）。**
9. **镜头序列含打斗/追逐时**：加载 `16-武术动作与动作指导.md` 走动作工作流——写Beat Sheet（事件/A状态/B状态/空间/情绪/优势）→ 拆成短动作单元（一镜一主动作）→ 每镜明确Start/End State和对手反应 → 按镜头覆盖表（宽中特宽）设计景别 → 用16号模板库生成Prompt+负面控制。战斗中每镜继承上一镜尾帧状态，不许"重新站好"。

### 模式E：全片工程（多场景/整片项目）

**加载优先级**：① `25`PROJECT MASTER(工程总纲) → ② `18`决策体系(每场戏意图) → ③ `24`状态机/Persistent State(跨镜状态) → ④ `22`Coverage矩阵(分场覆盖) → ⑤ `11`/`15`/`17`锁定。

用户要做整部短片/连续剧/多场景项目时进入：

1. 先建 **PROJECT_MASTER**（按 `25-Seedance控制与Prompt执行层.md` 的六层结构 + 参考 `11-全片一致性与工程系统.md`）：一句话视觉概念、画幅、主帧率、镜头家族、色彩母系统；同时建立资产参考层（角色/场景/道具/Look 参考图）与固定层/变量层结构。
2. 建角色卡（身份/服装/皮肤/动作DNA）、场景卡（空间规则+视觉锚点）、道具护照（重要道具）。**人物站位锚定**加载 `15-人物站位与场景一致性.md`：确定每个角色的人物锚点、Blocking Map、Camera Zone、固定区与变量区，建立Master Blocking Frame，后续所有镜头从母站位图继承Start/End State。**人物表演锁定**加载 `17-微表情与人物表演.md`：为核心角色建Character Performance DNA（眨眼习惯/眼神模式/讲话节奏/手势频率/情绪外显率/标志性微表情），镜头间用表演四锁（Identity/Performance/Emotion/State）防止角色"换演员"式表演跳变。
3. 采用**母Prompt+变量Prompt结构**：固定母Prompt描述影片DNA，每个镜头只写变量，禁止每镜重新定义风格。
4. 以**镜头组 Sequence**为单位组织（对话戏/追逐戏/情绪戏/史诗场面各有组织法），组内先统一，再跨组统一。
5. **整片生成拓扑与状态账本**（加载 `26-图生视频分镜衔接工程.md` + `24` 的 Persistent State/状态机）：确定星形/链式/混合结构，指定关键帧锚点、链式长度上限（≤5 镜）与回注节奏；建母图集（角色/场景/道具）；用 `24` 的五类状态(Identity/Spatial/Performance/Camera/World)建立跨镜状态账本，每镜登记 End State 七要素与尾帧评级。
6. 交付前跑一遍11号文件的质检表（12项）+ 18号文件的衔接评分（100分，及格70）。

### 模式F：视频参考拆解（从经典片段反推 Prompt）

**加载优先级**：① `14`参考库 → ② `18`决策树(反推意图) → ③ `19`视觉心理(注意力/权力位置)。

用户提供参考视频、片名、经典场景描述，或说"我想要XX片那种感觉"时进入。本模式让14号词库从"知识库"变成"可用工具"。

1. **定位参考**：加载 `14-经典片段参考库.md`，按用户提供的信息走三层索引定位：**先经 `18` 的"导演决策树"判断该片段服务于哪种 Scene Objective 与 Director Intent**，再用 `19` 的视觉心理分析其注意力引导与权力位置设计——从技法反推"为什么这么拍"。
   - 给了片名→作品级索引（查该片的代表场景+镜头）
   - 给了场景描述→场景级索引（查相似场景的经典解法）
   - 给了具体镜头描述→镜头级索引（查该镜头的九层拆解）
   - 只给了"感觉"（如"孤独、雨夜、跟拍"）→走反向入口9种之一反查（按视觉效果/摄影机运动/场景/情绪/灯光/剪辑/声音/叙事功能/AI制作目标）
2. **逐镜拆解**：按14号标准逐镜拆解表填写九层（叙事/表演/场面调度/摄影/灯光/美术/声音/剪辑/类型），填不出时参考14号30例实例库中同类的拆解。
3. **四层抽象**：走四层抽象模型——表面描述（"雨夜跟拍走路"）→视觉层（"低机位35mm手持跟拍，湿街反光，前景车顶掠过"）→机制层（"运动速度与步频同步，环境运动受控于雨水节奏，光源来自店铺霓虹"）→**第四层·可迁移规则**（"跟拍走路=机速=步频，湿街反光=低机位+硬反射面，孤独感=前景遮挡+环境冷光+人物只占画面1/3"）。**真正应该进入AI知识库的是第四层。**
4. **AI转译**：按AI转译模板四步输出——原始镜头描述→技术分析→原理化→AI Prompt。输出时可叠加08号灯光+09号色彩+10号风格签名做质感升级。
5. **相似度校验**：如用户提供了参考但不确定是否合适，用四维标签系统（内容/类型/技法/情绪）+相似度评分模型（30%视觉+20%摄影+15%场景+15%情绪+10%叙事+10%声音）打分，语义相似≠视觉相似，必须分开判断。
6. **看片对照**：如用户有多个参考想比较，用看片对照10模式（双片段并排/逐镜/冻结帧/参数/叙事功能/同题不同解/同技法不同类型/时间线/声音波形/镜头轨迹）做对照分析，帮用户选出最值得迁移的技法。
7. 输出最终AI Prompt + 拆解说明（从哪部片子的哪个场景迁移了什么可迁移规则），让用户知道Prompt的来源逻辑。**参考对象是动作/打斗场景时**（如某片的巷战、对决），叠加 `16-武术动作与动作指导.md` 的"经典动作参考抽象法"：抽象出Combat DNA（TYPE/CHARACTER/SPACE/MOVEMENT/ATTACK/DEFENSE/RHYTHM/CAMERA/LIGHT/SOUND/REACTION/ENVIRONMENT/EMOTION），再按16号AI动作工程（Beat+Start/End State+反应+连续性）转译成Prompt。

### 模式G：图生视频链式生成与分镜衔接（强烈推荐用于多镜项目）

**加载优先级**：① `26`图生视频衔接(必) → ② `24`行为控制(编译/诊断) → ③ `25`执行层(组装/质检) → ④ `18`(若需重设计镜头意图)。

用户提供/要生成上一镜的画面或尾帧、要做首尾帧、或要求"上下镜无缝衔接/连续生成/不换脸"时进入。**必加载 `26-图生视频分镜衔接工程.md`**。

1. **先定拓扑**：星形（统一母图，一致性高但硬切）/ 链式（尾帧→首帧，衔接顺但漂移）/ **混合（推荐）**。链式连续不超过 5 镜，第 4~5 镜必须做锚点回注（母图直注 / 图生图融合校正 / 交叉覆盖）。
2. **选接法**：同机位连续动作 → M2 尾帧继承；动作要精确落点 → M3 首尾帧双锁；景别跳两级或过轴 → M4 桥接帧或 T3 遮挡桥接；换场景换时间 → M3 或 T7 同构衔接。
3. **评尾帧**：抽尾帧做 A/B/C/D 评级。A 直接用；B 图生图轻修（重绘 0.2~0.35）；C 换接法（T3/T5/T7）；D 不修，退回母图重新起。**一致性 > 衔接**，冲突时宁可硬切不可换脸。
4. **查接缝**：用「接缝七要素」（姿态/方向/景别轴/光色/道具/环境/情绪）逐项 0-2 打分。12-14 分直接接；8-11 分补修失配项；5-7 分必须桥接或换掩盖型技法；≤4 分重新设计。同时核对 30 度法则（角度差 <30° 且未跳景别 = 跳切感）。
5. **写 I2V Prompt（六句式）**：①首帧锚定 → ②运动启动 → ③镜头声明 → ④环境激活 → ⑤收束定型 → ⑥一致稳定。**只写增量，图里已有的不重复描述**（重复 = 模型重绘首帧 = 换脸）。图不动时补②运动启动句或调运动强度；画面炸开时走 T8 静止起步拆两镜。**六句式写完后经 `24` 行为控制做最终清洗（去抽象形容词、核对一镜一变量），再按 `25` 执行层组装为平台 Prompt（固定层+变量层）与批次管理。**
6. **为下一镜留接口**：每镜 Prompt 结尾必写「收束定型句」——结束时人物停在哪、什么姿态、看向哪，这是链式生成的生命线。
7. **登记账本**：生成完一镜就填跨镜状态账本（首帧来源/评级/End State 七要素/尾帧评级/下一镜接法/Prompt 增量）。**正反打不链式继承**——反打用母角色图单独生成，视线、前景肩位、光位全部反向。
8. **验证顺序**：先用低分辨率 + 5 秒验衔接，通过后再出 1080p。后期只做 1~3 帧的微调掩盖，不做主要手段。

## 七大铁律（任何模式下都必须遵守）

1. **一个镜头一个主动作**：不要在单个镜头中同时安排跳跃+翻滚+三次攻击+转身+360环绕+甩镜。动作越多，AI 运动越失控。拆成多个镜头。
2. **人物运动必须有方向**：明确从左向右/从右向左/向镜头/远离镜头/围绕主体/沿纵深。
3. **摄影机运动必须与人物动作建立关系**：不写"人物走路，镜头电影感"，要写"人物向前走，摄影机同步向后跟拍，保持稳定距离"。
4. **环境不能完全静止**：加入云、雾、树叶、衣摆、发丝、光束、水面、粒子、花瓣的轻微、合理、连续运动。
5. **前景是空间感的来源**：经常使用前景树枝/人物/建筑/烟雾/花瓣/光影，并让前景产生运动以增强视差。
6. **每个镜头的结尾都为下一个镜头服务**：多镜项目必写 End State（人物停在哪/什么姿态/看向哪），让上一镜尾帧能直接当下一镜首帧；图生视频只写"增量"，不重复描述图中已有内容。
7. **杜绝无法执行的抽象形容词**：不写"电影感/震撼/唯美/高级感"等形容词，必须经 `24` 行为控制引擎的"形容词清洗器"转译为可观测的摄影变量（具体机位/焦距/运动/光位/景别）。AI 只能执行能看见的动作，执行不了形容词。

## 执行优先级

当 Prompt 要素过多、AI 难以全部执行时，按此优先级取舍：主体一致性 > 主体动作 > 摄影机基本方向 > 景别 > 构图 > 光线 > 环境运动 > 复杂特效。镜头再漂亮，主体和动作不稳定，成片不可用。

> 复杂度预算参考 `24-AI视频生成行为控制引擎.md`：单镜承载要素超限时按"降复杂度顺序"（先减环境复杂度→再减摄影机运动→最后减主体动作）收敛；并把"电影感/震撼/唯美"等抽象形容词经其"形容词清洗器"转译为可观测的摄影变量（如"电影感"→"低机位 35mm 缓慢推进 + 浅景深前景虚化"），不写模型无法执行的形容词。

## 负向控制原则

优先正向描述，不堆砌"不要……"：

- 不写"不要抖" → 写"锁定机位，构图完美稳定"
- 不写"不要人物变形" → 写"人物结构稳定，身体比例一致"
- 不写"不要背景乱动" → 写"建筑背景稳定，环境运动受控"
- 不写"不要突变" → 写"动作连续自然，运动轨迹稳定"

## 输出规范

- 输出 Prompt 以中文为主（Seedance 对中文原生支持最好），关键镜头术语可附英文关键词（如 Slow Dolly In）。
- Prompt 为连贯段落式（非关键词堆砌），包含明确的时间顺序（镜头开始→中段变化→结尾状态）。
- 每次输出 Prompt 后附简短的"导演设计说明"：主镜头/辅助运动/转场方式/为什么这样设计。
- 多镜头/整片项目额外交付：`18` 号的"镜头决策卡"（每镜 Scene Objective / Director Intent / 信息接力关系）与 `26` 号的"跨镜状态账本"（首帧来源 / End State 七要素 / 尾帧评级 / 接法），作为后续生成与质检的依据。
